# 软推荐搭配先验 Soft Recommend Priors（2026）

> **不是答案库，是「用户没说全时」的常见搭配起点。**  
> 网站导演台：`skill-guide-site/assets/dim-recommend.js`（与本表同构）。  
> 三 skill **必须**遵守下列铁律，避免写死、只会一种出片。

---

## 0. 定位

| 是 | 不是 |
|----|------|
| 网络/穿搭/摄影习惯里的**高频公式** | 唯一正确穿法 |
| 用户只点了「半身裙」时的 **fill 建议** | 禁止其它 L3/L4 |
| 可给出 **主推 + 1～2 备选** | 必须背表回答 |
| 可在释义写「常见搭配：…」 | 用户一改搭配就判错 |

**优先级（强制）：**

```text
用户原话 / 明确点名
  > 锚定成套补全（本线 references/anchor-ecosystem-fill-2026.md；联网可用时先联网内化该锚生态）
  > 命名组合包预填
  > 软推荐先验（本文件 / dim-recommend）
  > skill 默认快配
  > 模型自由补全
```

锚定成套补全只填仍空的维：组合包已预填的维不覆盖；用户已写的维永不覆盖。

## 1. Skill 写作时怎么用（防写死 · 核心）

### 1.1 运行时算法（内化，勿对用户背书）

```text
1. 扫描用户已指定的维（姿/衣/场/光/鞋/妆/发…）
2. 已指定维 → 永不被软推荐覆盖
3. 仅对「空维」：命中锚（单品/版型/场景/光/配件）→ 查本线锚生态表（联网可用先联网）→ 用成套生态填空维（场景+道具+造型+穿搭+光+姿+色彩协调）；未命中锚 → 走 trigger 表用主推填 1 套；可一句提备选
4. 用户说「冷门 / 反差 / 不要套公式 / 随机 / 换一版」
   → 刻意偏离主推：走 alts 或跨区混搭
5. 用户只说情绪（清冷/纯欲/名媛）→ 可走美学壳推荐，仍允许矛盾混搭
6. 推荐与 skill 专属冲突 → 专属边界优先
   （Figure 不因推荐默认内衣；Youth 不因推荐写连接点；Erotic 不因推荐改成 SFW）
```

### 1.2 话术铁律

| 允许 | 禁止 |
|------|------|
| `（空维按常见街拍公式补：midi 裙+乐福，可改）` | `半身裙只能配乐福` |
| `主推西装通勤；备选西装裙套` | `标准答案是…` |
| 用户改掉后直接跟用户 | 劝回推荐表 |
| 问「一定要这样吗」→ `不是，高频起点；要机能/礼服可整套换` | 暗示偏离=错误 |

### 1.3 为何 skill 不会「只会推荐答案」

1. **表是 prior 不是 policy**：覆盖率故意不全；未命中 trigger 走默认/自由补全。  
2. **主推 + 备选**：同一 trigger 至少可走 2 条叙事线。  
3. **空维才填**：用户写满了就等于关掉推荐。  
4. **偏离指令优先**：随机/反差时**禁止**复读主推。  
5. **网站与 skill 同构但职责不同**：网站一键填表可改；skill 写正文时只把 prior 内化成可画句，不复读 ID 表。  
6. **联网趋势**（用户问流行 / 点名锚求成套）可**临时覆盖**本表；内化结果若 ≥2 来源共识且可画 → 按**季度回流**写进本线 anchor-ecosystem-fill-2026.md（标 quarter + source，版本升 Q）；未达共识的只在当次对话使用，不写死。

## 3. 输出时的话术模板

- 填空时：`（空维按常见街拍公式补：midi 裙+乐福，可改）`  
- 用户改掉后：直接跟用户，**不要**劝回推荐。  
- 用户问「一定要这样吗」：`不是，这是高频起点；你要运动机能/礼服我可以整套换。`  
- 用户要「反差」：主推改对立维（例：半身裙 + 工装靴 + 硬侧光），释义标 `偏离先验`。

---

## 4. 与组合包 / 导演台关系

| 层 | 是什么 | 粒度 |
|----|--------|------|
| **组合包** | 一整幕预填（有故事名） | 粗、整 |
| **软推荐** | 点到某一 L2 时的局部亲和 | 碎、可叠 |
| **导演台一键** | UI 应用 merge 数组（经 `FIELD_POLICY` 清洗） | 可改、可不用 |
| **Skill 写作** | 只对空维内化成英文句 | 不锁死 ID |

并存：组合包打底 → 用户点「半身裙」→ 提示裙向推荐 → 用户决定是否应用。

**多选别混：** 软推荐 merge 若带多个互斥 L2（如五个发型造型），导演台会 **同 group 挤成 1 个**；skill 写正文时也只保留一个主造型 + 修饰。详 `docs/公共维度schema-L1L2L3.md` §0.1。

## 5. 维护

- 改推荐数据：优先改 `skill-guide-site/assets/dim-recommend.js`，再同步本摘要表。  
- 三 skill 各有一份本文件副本，内容应一致。  
- 新增 trigger 时：**至少 1 条主推 + 建议 1 条备选**；`source` 写清「穿搭/摄影习惯」一句话。
- 锚生态表 `references/anchor-ecosystem-fill-2026.md` 每线一份，随季度回流更新；同锚主推需进导演台时先改 `dim-recommend.js`，再同步本摘要表。
